# HOKU — етапи публікації та захисту

## Вихідні файли
- `Roast_Original_GitHub_Ready.zip` — вихідний шаблон Roast / Freeframe (без змін).
- `HOKU_GitHub_Ready.zip` — адаптований односторінковий HOKU.
- Обидва ZIP треба **розпакувати** перед завантаженням у GitHub. Завантажувати **вміст**, а не сам ZIP: `index.html` має бути в корені репозиторію.

## GitHub Pages
1. Створіть два окремі публічні репозиторії (напр., `roast-original` і `hoku-coffee`).
2. Перенесіть **вміст** відповідної розпакованої папки до кореня кожного репозиторію. Не потрібно вкладати файли в зайву папку `HOKU` чи `roast`.
3. Settings → Pages → Build and deployment → Deploy from a branch → `main` → `/(root)` → Save (для кожного репозиторію).
4. Перевірте на публічних сторінках: стилі, зображення, каталог, рецепти, кошик, навігацію та мобільну версію.
5. Збережіть обидва URL для звіту Word.

## Вимоги, які не можна вважати виконаними до зовнішніх дій
- Google Analytics 4: створити вебпотік, отримати вимірювальний ID `G-...`, вставити справжній Google tag у `<head>`, перевірити тестові події у Realtime/DebugView.
- Microsoft Clarity: створити проєкт, отримати ID, вставити реальний код відстеження, перевірити записи й теплову карту.
- Знімки екрана та метрики за фактичний період. Жодні статистичні значення не вигадувати.
- Word-звіт для Moodle з обома URL, скриншотами GA4 і Clarity та поясненням змін HTML/CSS.

Пункти про студентські зовнішні посилання, зворотні посилання та OpenLinkProfiler у наданій методичці закреслено: вони не входять до плану.

## Сценарій перевірки навчальної воронки
Перегляд каталогу (`view_item_list`) → відкрити каву (`view_item`) → додати в кошик (`add_to_cart`) → відкрити кошик (`view_cart`) → почати оформлення (`begin_checkout`) → завершити тестову заявку (`generate_lead` і `demo_order_complete`). Оплата не виконується, `purchase` не надсилається.

## Попередній локальний контроль
- 7 варіантів зерна, 4 рецепти, 3 фільтри смаку і 1 навчальна корзина.
- Заповнені `title`, `description`, `h1` із ключовою фразою про спешелті каву.
- Зображення WebP, логотип PNG, відповідні alt; зображення каталогу завантажуються відкладено.
- Текст-попередження з методички міститься у футері без змін; підпис Burenko Polina теж там.

Примітка: шаблон Roast ізбережено як оригінал. У HOKU незміненою залишено базову CSS-збірку оригіналу, а HTML і сценарії JS переписано під новий односторінковий проєкт.
